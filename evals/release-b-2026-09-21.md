## What each change did, as observed

- **Docs-first classification.** The agent said "docs-first" in those words, inventoried and
  classified the three vision docs (contract, history, history), recorded the two dated
  decisions, and stopped on the planted contradiction as the reconciliation step requires,
  putting it to the user with options rather than picking one. Nothing under the vision folder
  was touched.
- **Git shape.** Every run that started from a repository, or could create one, worked on
  `bootstrap/fieldnote`, named the starting SHA in the first commit on the branch, committed per
  step, and wrote no branch rule into the project. One agent made the SHA commit empty because
  no file existed yet; the rule allows it and the eval accepts it.
- **Open questions as pointers.** No run wrote an open-questions section into a design doc. All
  of them created `<project>/docs/OPEN-QUESTIONS.md` from the template the moment a question
  arose, before generation, and pointed at it from the doc.
- **Compressed mode.** The run wrote the golden example first, the docs in dependency order,
  added the "revisit these, least review" row before generation with the milestone it blocks,
  and named those docs in the final message. It then carried on into the first session, which
  the new git section invites; the "no stub plans" assertion had to be sharpened to "no plan
  left at `grounding`" to stop counting a real, claimed plan as a stub.
- **Forward citations.** Three runs reported only `W007` warnings for the docs later steps
  create, and none invented a workaround. The one remaining rewording was a citation to the
  phase-start versioning doc, which generation does not create either; the agent was right to
  reword it.
- **First claim flips the milestone.** Both runs that claimed did it in the same edit as the
  plan and the feature line, and regenerated the indexes rather than editing them.

## Gaps this round exposed for release C

- `.gitattributes` and the plugin-versus-project hook choice are still unspecified at
  generation; every run left the hook decision to the user, which is fine, and none wrote the
  attributes file, which is not.
- Two runs rewrote the `{{date}}T{{hh}}:{{mm}}Z` hint and the embedded templates in
  `<project>/docs/WORKFLOW.md` into angle brackets by hand; the template should ship them that
  way.
- Every generation run inlined an ADR template because the pointer to `assets/templates/adr.md`
  does not resolve in a project. Ship it into the project or inline it in the template.
- One design-doc run cited `docs/design/versioning-and-compat.md`, a phase-start doc, and had
  to reword it; a citation to a doc the profile schedules for later is a real case the forward
  citation rule does not cover. Worth deciding whether it should.
