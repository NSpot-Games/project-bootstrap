## The 45 improvisations

The count rose from 40 because the run reported finer grain, as the invented runs did in their
third pass. The forty-five triage into seven distinct procedure gaps covering nine of them,
thirty-two clarifications and four that are not gaps. None of the seven is one that release F
closed, and none is in the setup, the gates, the git shape or the first session; all sit where
a docs-first repository or the curated-directory profile meets a rule the procedure states
for the general case.

1. **Docs-first repositories need the linter config before generation.** The read-only lint
   after the relink commit reported two errors and ninety-one warnings from frozen history,
   so the run created the config early with the history excluded and a `minimal` pin, then
   had to move the pin to `lite` when the roadmap appeared and to `standard` at generation.
   §6a should create the config with the exclusion at the relink commit and say the pin
   follows the tiers as the files arrive.
2. **The docs map's classes disagree with the adoption reference.** The template offers
   history, research and external reference; the reference uses contract, history and
   external reference. A doc that was contract at bootstrap and is history after has no
   class, and a contract for a phase whose design docs are not written yet has nothing to
   be superseded by. One vocabulary, in both places, with those two cases named.
3. **Any backticked bare filename in prose is a citation.** Three errors in the docs map and
   two ADRs; the second run to hit this. `skills/project-bootstrap/references/core/doc-kinds.md §3` warns only about bare readme
   names. One sentence, and the linter's message could say it.
4. **The kit's `tools/` and a project's own `tools/`.** §4 fixes the kit's paths without
   saying how they coexist with a project that already plans tooling there.
5. **Secrets when the profile has no security doc.** §4 step 2a says "any secrets file the
   security doc names"; the curated-directory profile has a legal-and-privacy doc that names
   none, and the secrets live in the architecture doc. Say "whichever doc names them".
6. **A constructed stand-in.** The profile wants a real entry; the project's own rules forbid
   real personal data in examples; §3(b) allows a constructed instance but says nothing about
   how invented values are marked (reserved domains, impossible dates, zero identifiers) or
   whether related entities belong in the one-entry folder. The profile's §4 should cover a
   project whose rules forbid real data.
7. **Sketches beyond the template's one.** The source named an eleven-step build order and
   four later phases; §3(c) says the template's second phase stays as it ships without saying
   more sketches may be added when the source names them.

## Where this leaves the kit

Six releases on from the audit. The procedure has now held on three invented runs and two real
ones; the seven gaps release F closed did not recur, and the seven this run found are the next
layer down: the linter's life before generation in a docs-first repository, one vocabulary for
classifying old docs, and the seams a constructed example and a rich source open. A release G
closing them is again about a day of text and one rerun. After that, the remaining profiles
have never met a real repository, and each first use will find its own seams.
