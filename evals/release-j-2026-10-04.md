# Release J (v2.10.0): tracker sync, verified, 2026-10-04

Version 2.10.0 lets a project mirror its milestones and features onto a GitHub Project.
`skills/project-bootstrap/scripts/sync_tracker.py` (copied to `<project>/tools/`) keeps the
repository as the source of status and the board as a one-way mirror plus the claim lock: a
session runs `claim <id>` before it writes a plan and stops when someone else is assigned; `sync`
creates milestones and issues, moves cards and writes a `(tracker: #N)` link last on each feature
line; a merged PR with `Closes #N` moves its card to Done through the project's built-in
workflow. The linter reads the link anywhere on a feature line, validates the `[tracker]` table
(`E012` at the lite tier) and warns (`W009`) on a planned feature without a link. Spec:
`docs/superpowers/specs/2026-10-04-tracker-sync-design.md`. Verified with the per-step
scenarios, now nine, two of them new and driven by `evals/fake_gh.py`; a live run against
GitHub is recorded separately below.

What the runs showed:

## Final review

A fresh reviewer read the whole branch: no Critical findings, six Important, eight Minor. The
six Important were fixed in one pass, each with a test that failed first:

1. `sync` never moved a link that sat before the plan path; it now does.
2. and 3. The default-branch guard could be bypassed by a failed fetch and refused the
   generation step on the bootstrap branch. `sync` now compares `HEAD` with GitHub's own head
   of the default branch and, from a tree that lacks a merge, applies everything except the
   changes that would take a feature back out of Done, listing those as skipped.
4. Fixed list limits: lists now go to 10,000, linked issues past them are fetched one by one,
   and milestones are paginated.
5. A claim race on a feature with no issue yet went unseen; the re-read now checks every issue
   carrying the feature's ID.
6. `done` milestones created issues; they now only match existing ones, as the spec scopes.

The eight Minor findings are deferred; they are listed in the pull request.

The scenario runs above were made before the fix pass. The fixes touched `sync_tracker.py` and
the fake; `test_harness_prepares_tracker_scenarios` runs the claim against each tracker
scenario's prepared project after the fixes and still gets exit 0 and exit 3.
