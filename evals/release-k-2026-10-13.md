# Release K (v2.11.0): idea-to-design, verified, 2026-10-13

Version 2.11.0 adds a second skill, idea-to-design (`skills/idea-to-design/`), which turns a raw
idea into a design in `<project>/docs/vision/`. The package tests now run over every skill. The
eval harness gained a per-scenario `skill` key, a `--no-skill` baseline mode and the
`final_count` check, and it reads non-UTF-8 files (8cf9726). Six new scenarios run on four
invented Tidepool fixtures. project-bootstrap §1 now offers idea-to-design when the user brings
a bare idea. The README, BOOTSTRAP.md, AGENTS.md and the manifests describe two skills.

All eval agents ran on the same mid-tier model (sonnet).

## project-bootstrap regression

Three changes in this release reach project-bootstrap's scenarios. The §1 change touches only
the path where the user brings a bare idea. The other two touch all nine project-bootstrap
scenarios: the harness PROMPT was reworded so it names no one skill ("Paths written as
`<project>/...`", "If the work requires…", "which steps you followed" in place of the
project-bootstrap wording), which changes what every agent reads; and `_read` now decodes a
non-UTF-8 file instead of treating it as empty (8cf9726), which changes how a file written in a
Windows code page is graded. The owner chose to re-run only the two scenarios on the bare-idea
path: docs-rich-greenfield 6/6 and generation 20/20. The other seven project-bootstrap scenarios
were not re-run, to save cost.

## Assertions changed during the release

1. raw-idea: the release first widened "names what is new" and "question is about purpose" to
   accept step 1's already-exists path, after a run judged neighbourhood tool lending to already
   exist (Peerby, Fatllama). The final review found the prompt was a bare category that really
   exists, so the scenario could not test the purpose path. The widening was reversed. The prompt
   became an idea with a visible new element, the purpose-path assertions were restored, and a
   check was added that the message does not declare the idea a copy.
2. The question count in raw-idea and tech-drift became `(?m)\?[\s*)]*$`. A `?` followed by a
   closing quote is a quoted example, not a question.
3. Earlier, in Task 3's review: handoff's stack pattern, nothing-new's patterns, and the
   Tidepool fixtures' unplanted "borrowing is free" contradiction.
4. consistency gained three file checks, so "fixed in the files" is graded on the files and not
   only on the report: trust.md no longer says "more than 5 days" or "3 tools", and the vision
   README no longer says "3-tool". Each check fails on an untouched copy of vision-flawed.
5. handoff's `unchanged` check widened from the area files to every vision file, README
   included. Its still-to-design pattern now names the open items.

## Skill changes driven by the evals

- The doubled question (a lead-in question plus "which one?") is gone: the lead-in names the open
  question as a statement, and the only question mark is on the last line.
- Eval-domain words were removed from the skill, so the evals measure the method and not the
  vocabulary.
- The description now covers resuming a design under way.

## Known limits

- The nothing-new hijack, where an installed project-bootstrap grabs a bare idea, is a trigger
  question between two skill descriptions. The evals load the skill directly, so they cannot
  test which skill an agent picks. The §1 offer line in project-bootstrap is the mitigation.
- The handoff baseline is contaminated, so its 6/6 does not show what the skill adds.
- Step 1's two paths are each tested by one scenario: the purpose path by raw-idea, the
  already-exists path by nothing-new.
