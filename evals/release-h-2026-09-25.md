# Release H and I (v2.9.0): agent economy and the carried gaps, verified, 2026-09-25

Version 2.9.0 ships three things on one branch: release H (the agent economy, below), release I
(the six gaps the release G run found and the six minors the release H review deferred) and the
fix for issue #13 (a non-numeric `stale_hours` is now `E012`, not a crash). The first half of this
file verifies release H on its own; the last section verifies the finished 2.9.0.

Release H made speed and economy the default for every bootstrapped project. A new core page,
`skills/project-bootstrap/references/core/economy.md`, says which tests earn their place, when
checks run (the task's check while working, the full suite once at Close), what CI looks like
(one workflow, a fast job under five minutes on pull requests and a slow job on merge or
nightly, a path filter, no deploy pipeline before the milestone that ships, one local `check`
command), how an agent works for a human (stopping rules, Done when and Stop and ask if, a
blocking-only self-review, questions logged with a default, a session report that opens with
Needs from you) and which instruction habits to drop. The lifecycle, the plan and project
templates and six profiles' architecture rows carry it; plan-lite
(`skills/project-bootstrap/references/core/lifecycle.md §3a`) gives features of three commits
or fewer a shorter plan, and the linter warns (`W008`) when a lite plan grows a fourth task.
Verified the same two ways as release G: the per-step scenarios, now seven, and a fourth full
run on the same real repository from the same seed commit, with the reviewer as owner, scored
with `rubric.md`. This file records only the shape of the run and its numbers, never the
project's content.

## The 35 improvisations

None concerns the economy rules. They fall into the six gaps release G's run already listed and
the user chose to keep for a later release — the bootstrap's own recommendations while writing
(four lines here), a delegated contradiction read as the owner's decision (one), edits and
schema extensions after a gate (two), held gaps with interim behaviour (one), the carried-over
branch line (one) — plus clarifications in the same families as before: the `<core>` name,
where the example walkthrough sits, version-dotted names under kebab-case, relinking ranges and
headings in history, a vendored reference's class, carried-over Don'ts, `none` for an empty
dependency, and a bare filename in prose read as a citation. Two are new and small: sketch
milestones written as `Exit: TBD` under a named goal (lint-clean, but the roadmap template
shows no exit line for a sketch), and a hours open question that blocks no feature being given
a milestone to block.

## Where this leaves the kit

The economy rules landed without moving the score: 69/69 on the scenarios and 23 / 1 / 0 on the
real repository for the fourth time, with no gap a release closed coming back. The generated
project now tells its agents to check what the task needs, run the full suite once, keep CI to
one lean workflow and put the human's decisions first. What these runs cannot show is the speed
of feature work itself: every scenario ends at the bootstrap, so the saving is in the first
project that runs features under 2.9.0. The next release is the six carried gaps.

## Release I folded in, and the whole of 2.9.0 verified

Release I wrote the six carried gaps into `skills/project-bootstrap/SKILL.md`: a value the
bootstrap chooses alone is a recommendation, with a row only when it is expensive to change; a
delegated contradiction is an owner decision and needs no row when settled before the
open-questions file exists; an edit after a gate is named in the next gate message when it
changes a decision, and a contradiction between two reviewed docs goes to the user; a gap found
early is *to fold*, and a held gap states its interim behaviour; a feature may be any work its
exit needs; the carried-over workflow drops a line that names the bootstrap branch. The six
minors landed too: plan-lite's one to three bullets, `E013` over `**Shape:**` documented in
`skills/project-bootstrap/references/core/layers.md §3`, the open-questions default written as
`none — default: …`, pushing the project's own branch allowed, and the wording fixes.
