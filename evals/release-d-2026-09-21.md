## The 24 improvisations, triaged

**Procedure gaps (4), the input to a release E if one is wanted**

1. Docs without a "decisions we're committing to" list have no home for the decisions the ADR
   backfill draws from, and the brainstorm's decision list is meant to stay off disk. The run
   added a decisions section to two docs. Either every profile outline carries a decisions
   entry, or §4 step 4a says the brainstorm list is written into the primary design doc.
2. Open-question rows have no lifecycle after the roadmap: nothing rewrites *Blocks* to IDs once
   milestones exist, and a row decided mid-bootstrap is deleted before its ADR exists at
   generation. §3(b) and §4 should say when a row becomes an ID and when it becomes an ADR.
3. A later decision that contradicts an earlier design doc mid-bootstrap has no rule; the run
   went back and edited the earlier docs with changelog entries in the same commit. That is
   right and should be written down.
4. Decisions the owner made in the brainstorm and the agent's recommendations both become
   `proposed` ADRs, so the owner re-accepts what they already decided. Step 4a could mark
   owner-made decisions differently, or say why not.

**Clarifications (19)**: naming a moved history file; where "recommended, not confirmed" markers
live; fixture format when the schema is an ORM's models; where fixture-exposed gaps go on
profiles without a gaps section; where held-for-M0 gaps live before the milestone file exists;
the ADR *Deciders* field; ADR filename length; when two mechanisms are one decision; principles
sections without ADRs; template lines that are instructions rather than tokens; adding `.env` to
the gitignore; the plan's branch field versus the stamp's branch when claiming on the bootstrap
branch; removing the template's placeholder task; the agent name in a stamp; bare design-doc
filenames in the layout line; a pointer line on a doc whose outline lacks one; held gaps versus
the deferred list.

**Not a gap (1)**: the one-handback-per-turn delivery is the eval environment, not the skill.

## Where this leaves the kit

Four releases on from the audit: the linter is trusted, the procedure is followed rather than
improvised across, and the two verification layers (scenarios in minutes, a full run in half an
hour) are in place to measure the next change. The remaining friction is in details a sentence
each would settle, and in three seams worth a rule (decisions' home, open-question lifecycle,
revising earlier docs). None of them changed what the run produced.
